LEARNING PATH / LLM BASICS

LLM 入門

先搞懂 LLM 怎麼運作，再學它為什麼會出事。四堂互動課，每堂約 3～5 分鐘，做完再挑戰十大風險。

4 堂互動課
1Token→2機率與溫度→3對話與提示結構→4RAG 與 Agent→★十大風險
1

模型看到的不是「文字」，是 Token

LLM 會先把你的輸入切成一小塊一小塊的 token，再逐塊處理。輸入任何文字，看看它被怎麼切。

字元數0
Token 數（示意）0
以 $0.03 / 1K tokens 估算$0
這是簡化示意：實際的分詞器（例如 BPE）會依模型而不同，同一段話在不同模型的 token 數也不一樣。重點是：模型只看得到 token 序列，不會自動分辨哪些是「指令」、哪些是「資料」。
跟資安的關係輸入越長 token 越多，成本和處理時間就越高 → 　指令與資料混在同一串 token 裡 →
2

模型是「猜下一個字」：機率與溫度

LLM 每一步都會算出每個候選 token 的機率，再抽一個。「溫度」決定它多保守、多敢冒險。拖動看看。

提示：台灣最高的山是＿＿＿
按下「抽樣」看模型會選哪個詞。
這裡的候選詞與數值是教學用的示意資料。溫度低：幾乎每次都選最有可能的答案（穩定但單調）；溫度高：結果更多樣，但也更容易冒出不合理的答案（例如「富士山」）。
跟資安的關係模型本質上是在猜「看起來合理」的下一個字，所以會產生幻覺 →
3

一次對話裡，模型到底收到什麼？

開發者的設定、使用者的問題、外部文件，最後都會被拼成同一段上下文。試試加入外部文件，再讓它夾帶惡意指令。

跟資安的關係指令和資料混在一起，是間接提示注入的根源 → 　系統提示不該放機密 →
4

RAG 與 Agent：模型長出「手腳」之後

真實的 LLM 應用很少只有一個模型：會去查資料（RAG）、會呼叫工具（Agent）。一步一步看，每一步可能出什麼事。

RISK MODULE / LLM06

過度代理授權防禦

Excessive Agency · 限制 AI Agent 的工具權限，高風險操作必須經過人工授權。

HUMAN AUTHORIZATION

Agent 任務模擬

給 AI Agent 一項任務，看它規劃了哪些工具，再依右邊的權限設定決定每一步是放行、等你確認，還是直接封鎖。這裡不會連接真實帳戶，也不會執行任何操作。

工具權限設定

每個工具可以設成「允許」「需確認」或「禁止」。最小權限原則是：只開放任務必要的工具，高風險操作一定要有人確認。

展示環境不會連接真實帳戶，也不會執行任何金流或刪除操作。
